# Scenario Coverage

[Documentation home](README.md) | [Existing tools first](learning/00-start-with-existing-tools.md)

This matrix distinguishes existing supported products and enterprise tools from accelerator-added analysis. “Implemented” means deterministic code and synthetic tests exist; it does not certify a customer environment.

## Assessment Contract

Start with one unanswered engineering question and the smallest useful set of [checks](how-to/choose-recommendation-packs.md). The advisor is a local, deterministic, read-only assessment tool, not a resident controller. The retained CPU, memory, reliability, autoscaler, scheduling and capacity packs remain independently selectable; useful numeric paths require guarded mode and their separate evidence and owner-policy gates. A blocked dimension does not invalidate an independent observation.

| Boundary | What to agree before the assessment |
| --- | --- |
| Existing sources | Use approved ARG inventory, sanitized Kubernetes metadata and existing generic or Azure-managed Prometheus as required by the selected checks. Saved Advisor, VPA/HPA/KEDA/NAP and financial observations are optional context, not a requirement to install every tool or another monitoring stack. |
| Identity and quality | Retain exact resource IDs/fingerprints, source/profile/version, UTC clocks, units, receipt completeness and metric-specific coverage. Missing, stale, partial or ambiguous evidence remains unknown or blocked, not zero or healthy. Current metadata cannot reconstruct historical membership. |
| Fleet and replay | Compose independently verified saved cluster assessments with declared peer groups; Fleet Manager is not required. Current inventory/envelopes and repeated-finding counts do not establish historical usage, portability, placement or removable capacity. Keep original inputs, configuration locks and the compatible package for replay. |
| Optional finance | Project supported saved aggregates without a ledger, or use the separate ledger-backed reconciliation workflow. Allocation qualification checks declared scope, source time and exact assessment period; it does not order findings, upgrade name-only attribution or calculate savings. Engineering savings remain null. |
| Optional AI | Separately consented local summary export and original-artifact-backed explanation/checklist validation are offline previews. Accepted drafts remain unverified. No model is invoked, no richer data release is implied and no draft approves or executes a change. |
| Owner decision | Record retain, investigate, defer or seek independent approval to test one dimension through existing delivery tools. Findings, numeric proposals, hashes and successful exits are not approval or source authentication. |

The optional [saved startup investigation](data-contracts.md#saved-startup-investigation) brackets sampled Pod readiness and independently qualifies post-readiness usage; first-ever startup and application initialization remain unknown. [Offline scheduler calculations](data-contracts.md#offline-scheduling-resource-calculations) compare supplied CPU/memory/Pod-slot constraints and descriptive resource scattering while source/scheduler admission and fit remain blocked. Historical cluster envelopes, broader policy drafts and provider-backed preview remain unfinished. Optional cluster-only cost-review ordering and separately consented four-measurement local AI export have bounded offline implementations; neither establishes savings, provider-disclosure consent or release acceptance. These limits do not retire retained packs or remove required feature depth. Optional [retained-assessment quality export](recommendation-packs.md#retained-assessment-quality) binds original executed evidence without qualifying a live datasource or time picker. Actual Grafana runtime/source acceptance remains separate from generated JSON and synthetic tests. Headlamp product integration and automatic remediation are not part of this assessment workflow.

Use the [questionnaire](onboarding-questionnaire.md) to record the selected scope and evidence handoff. Do not collect Kubernetes Events, logs, arbitrary bodies, workload environment values, payloads or credentials to fill a gap. The [security boundary](security-and-privacy.md) applies to optional workflows as well as ordinary engineering analysis.

## Scenario Matrix

| Scenario | Existing foundation | Unresolved question and added evidence | Existing owner/workflow | Status and exclusions |
| --- | --- | --- | --- | --- |
| Current configuration | AKS inventory and admitted-Pod/controller metadata | Which placement, probe, topology-spread, PDB, missing-request or controller conditions deserve review? Use fresh exact-scoped metadata, not usage history. | Platform/application owner reviews existing manifests and backlog. | Metadata-only checks; no metrics or financial import required, no PDB selector match, generated configuration, packing or removable-node claim. |
| Ordinary CPU observation | Existing enterprise Prometheus/Grafana | What do scoped CPU usage/request series show when historical workload UIDs are unavailable? Retain unresolved measurements, dates/units and gaps. | Monitoring owner checks existing labels; application owner reviews demand and intentional reserve in current dashboards. | Baseline only with `cadvisor-ksm`; no ownership enrichment or numeric targets, no new recordings required. |
| Azure financial ledger | Cost Management exports or FinOps hubs/FOCUS | Does optional allocation preserve basis, amounts and exact historical resource bindings? | FinOps owner links the reconciliation to existing ledger/chargeback review. | Offline projections and bounded native FOCUS CSV/manifest conversion; no billing/ADX/Fabric/storage client or currency conversion. |
| AKS namespace/asset attribution | Managed AKS Cost Analysis | What separate workload evidence could explain source-native attribution without upgrading it to workload history or savings? | FinOps/platform owners retain the portal view and existing investigation. | Attribution-only profile; [offer/scale/latency/identity limits](financial-source-profiles.md#aks-cost-analysis-applicability) apply; no public add-on API assumed. |
| OpenCost/Kubecost attribution | Existing customer installation | Are pricing provenance, period and idle/shared policy compatible with the optional billing workflow? | Existing cost-tool owner and FinOps review, without replacing their dashboards. | Characterized saved projections; ordinary list-price estimates remain estimates in the upstream tool, not invoice actuals here. |
| CPU request candidate | Saved VPA status or characterized Kubecost candidate projection | Does an exact per-container upstream target pass freshness, admitted request, peak/policy, throttling/reliability and controller gates? | Application/platform owner approves or defers one CPU experiment in current delivery tooling. | No competing request target; saved VPA generation age and qualified history are separate facts. |
| Memory request candidate | Saved VPA status or characterized Kubecost candidate projection | Does the exact upstream target pass full-grid memory/reliability history, peaks, QoS/admission and explicit owner opt-in? | Application owner owns memory-specific validation/rollback; CPU readiness is not memory readiness. | Memory limit remains separate; missing candidate/history/age blocks rather than deriving a new target. |
| Azure Advisor findings | [Azure Advisor AKS recommendations](https://learn.microsoft.com/en-us/azure/aks/cost-advisors) | What workload/controller/reliability evidence is still missing after the existing finding? Preserve its ID/version/time/scope. | Platform owner annotates the existing triage record instead of duplicating enablement work. | Saved typed observation and annotation; no Advisor API client or per-container target conversion. |
| Workbook investigation | [Cost Optimization workbook](https://learn.microsoft.com/en-us/cloud-computing/finops/toolkit/workbooks/optimization) | Does a resource-level rate/usage insight leave a specific workload-configuration or historical-evidence question? | Workbook/FinOps owner links the optional report from an existing review/change ticket. | No competing dashboard, workbook ingestion API or quick-fix authorization. |
| Existing optimization pipeline | [Azure Optimization Engine](https://learn.microsoft.com/en-us/cloud-computing/finops/toolkit/optimization-engine/overview) | Does an existing resource/Advisor investigation need exact workload, controller or reliability context? | Existing AOE operator retains its recommendation history and attaches a protected report reference to current triage. | No AOE deployment, hosted connector or native outbound import schema; any integration mapping is separate scope. |
| Fixed node-pool utilization | Existing Prometheus plus AKS inventory | Is constant-capacity utilization supported by full historical node membership and allocatable capacity? | Platform owner reviews current capacity planning, including intentional reserves. | Manual fixed-pool investigation only; NAP-managed/changing-capacity and node-removal simulation excluded. |
| NAP and controller interaction | AKS NAP, HPA, VPA, KEDA | Which current ownership/configuration and consolidation-readiness blockers remain unresolved? | Platform/controller owner reviews existing policy and deployment records. | Fresh metadata investigation only; no migration, policy change, packing/disruption feasibility, removable-node or node-count target. |
| DaemonSet overhead | Existing admitted Pod requests and current Node allocatable CPU/memory | Do identical effective DaemonSet requests occupy different fractions of different observed node shapes? | DaemonSet/platform owner reviews per-node demand, initialization and reliability requirements. | `AKS-NP-004`: current exact-identity metadata only; no usage claim, universal target, generated annotations, node eligibility, packing or savings. |
| Fleet placement | [Azure Kubernetes Fleet Manager](https://learn.microsoft.com/en-us/azure/kubernetes-fleet/overview) | What evidence and placement/resilience constraints should the fleet owner consider? | Existing fleet design/change review. | No placement engine or live migration; public prices are not reconciled customer savings. |

Select one row; adopting the others is not a prerequisite. Reports retain observations, missing evidence and blocked reasons, while owners decide whether to retain reserve, investigate, defer or independently test a change. No automatic AOE/workbook/Grafana publication is supplied, and no financial import gates engineering analysis. The [entry-point guide](how-to/choose-recommendation-packs.md#three-ways-to-start) maps each level to exact input and access requirements.

## Support Notes

AKS Cost Analysis is a managed Azure capability. FinOps Toolkit solutions are Microsoft-maintained but provided as-is; underlying managed products retain their own support contracts. OpenCost and Kubecost support depends on the customer’s installation and vendor/community terms. The accelerator’s source characterization is not product certification.
